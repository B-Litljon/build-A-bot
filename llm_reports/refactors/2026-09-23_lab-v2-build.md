(`aa4acb5d6958e3e4`, `frame_from_cache: true` on arm 2 — W1's exclusion of
`gate` from the frame hash is what made this work):

| metric | LightGBM | CatBoost |
|---|---:|---:|
| pooled OOS trades / wins | 30 / 13 | 94 / 17 |
| edge over random | +0.1793 | **−0.0731** |
| pooled PF lower bound | 0.7727 | 0.2692 |
| mean Brier | 0.0857 | 0.2502 |

consistent with the 2026-09-14 edge-budget conclusion. The delta itself is not
distinguishable from sampling noise at these counts (30 vs 94 pooled trades;
LightGBM's +0.1793 is the already-withdrawn small-sample artifact) — what IS
settled is that neither arm promotes, CatBoost with strictly worse evidence on
3× the trades.

## Post-implementation audit & fixes (by Antigravity)

A meticulous post-implementation review caught three concrete issues in the initial build, which were patched and pinned with tests:

1. **W1 Dataclass generator state hash collision & unhashability:**
   - *Issue:* In `FeatureSpec.content_hash()`, `asdict(self)` was used at the root. In Python, `dataclasses.asdict()` recursively converts all child dataclasses into plain dicts before `_jsonable()` is ever called on them. As a result, `isinstance(gen, BaseFeatureGenerator)` was false for dataclass generators, stripping `_generator_id(gen)` (causing distinct generator classes with identical field names to collide on the same hash) and bypassing `_generator_state()` (falling through to `json.dumps(..., default=str)` which serialized in-memory pointer addresses rather than raising `TypeError` on unhashable states).
   - *Fix:* `content_hash()` and `_jsonable()` now traverse dataclass attributes via `fields(obj)` / `getattr()`, preserving `BaseFeatureGenerator` instances so `_generator_state()` runs as designed.
   - *Tests:* Pinned in `tests/test_lab_spec.py` (`test_distinct_dataclass_generator_classes_with_same_fields_do_not_collide` and `test_unhashable_dataclass_generator_state_raises`).

2. **W3 Ablate CLI argument parsing:**
   - *Issue:* In `src/lab/cli.py`, `_add_spec_args(ablate)` was omitted from the parser configuration for the `ablate` subcommand. Running the documented command `python -m lab.cli ablate --name v3_base_control` failed with `argparse.ArgumentError: unrecognized arguments: --name v3_base_control`.
   - *Fix:* Added `_add_spec_args(ablate)` and unified argument flags (`--name`, `--spec`, `--bar-cache-dir`).
   - *Tests:* Pinned in `tests/test_lab_ablate.py` (`test_cli_ablate_parser_recognizes_spec_arguments`).

3. **W3 Ablate orchestrator runtime crashes:**
   - *Issue:* In `src/lab/ablate.py`, `_omitted_family(spec)` performed `spec.name.rsplit("_minus_", 1)[1]`, crashing with `IndexError` on the base spec (which has no `_minus_`). Additionally, the delta loop referenced `full.pooled_oos_wins` instead of `full_variant.report.pooled_oos_wins`, raising `NameError`. Finally, `_run_variant` failed to pass `n_folds` to `run_gate` on the base arm.
   - *Fix:* `_run_variant` explicitly accepts `family` and `n_folds`, `_omitted_family` safely falls back if `_minus_` is absent, `n_folds` is passed consistently to all arms, and deltas correctly reference `full_variant.report`.
   - *Tests:* Pinned in `tests/test_lab_ablate.py` (`test_ablate_orchestrator_runs_all_arms_and_computes_deltas`).
